# 引き継ぎ: Suicaのペンギン デジタルスタンプラリーの巡回ルート

作成: 2026-10-18。前のセッションで京王の全駅巡回ツールを作ったリポジトリ（`train-diagram/`）に、JR東日本向けの機能を追加して進めてきた。

## 1. 目的と現状

- **目的**: 「Suicaのペンギン デジタルスタンプラリー」（2026/10/1〜12/25、エキタグアプリ）の全20スポットを回るルートを、実際の時刻表から計算する。
  - 公式案内: https://media.jreast.co.jp/articles/6731
- **ユーザーが決めた条件**:
  - 土休日のダイヤで計算する。
  - 新幹線駅（仙台・新潟）は回るかどうかを選べるようにする。
  - 仙台・新潟を回るときは新幹線を使う。それ以外は在来線の普通・快速だけで移動する（特急・ライナーは使わない）。
- **現状**: 土休日なら **1日で20か所すべて回れる** ことを確認した（下の「6. 計算結果」）。
  - 時刻表の取得、全スポットの位置と時間、探索プログラムまではできている。
  - 出発する駅と時刻の指定、ダイヤグラムやスマホ用画面への表示はまだ。

## 2. ユーザーについての前提（作業の進め方）

- 報告や質問は日本語で書く。
- 実行環境は Deno 2.x だけ（node / npm はない）。Windows の Git Bash か PowerShell で動かす。
- コミットはローカルまで。GitHub への push は、ユーザーに言われたときだけ行う（リポジトリ: `pibv474p/keio-station-rally-route`、公開）。
- 時刻表データ（`raw/`、`data/`、`out/`）は再配布が禁止されているので、リポジトリに入れない。`.gitignore` 済み。
- スマホのエキタグアプリのスクリーンショットは、リモートコントロールを使い、Claude アプリから送ってもらえる。
  - 前のセッションで受け取った画像は、Claude Code のユーザーフォルダ（`~/.claude/uploads/` の下のセッションごとのフォルダ）に残っている。
- 徒歩の時間は、ユーザーが「想定より長くかかる」と感じている。短めに見積もらないこと。

## 3. 時刻表データ

- **取得元**: JR東日本の公式時刻表サイト https://timetables.jreast.co.jp/ （2026年10月号、URL の版は `2610`）。
  - ページは JSON の API ではなく HTML なので、HTML を解析して読む。
  - ページのつながり: 駅ページ `timetable/list<駅コード>.html` → 駅時刻表 `2610/timetable/tt<駅>/<駅><nn><0平日|1土休日>.html` → 列車ページ `2610/train/<nnn>/<file>.html`。
  - 列車ページには全停車駅の着時刻・発時刻・番線がある。1ページに、続けて走る列車が複数列で並ぶ（山手線の環状運転や、途中で列車番号が変わる場合）。
  - 新幹線の通過駅は空欄なので、データには入らない。
- **利用条件**: サイトに「交通新聞社 JR時刻表 に基づく。無断転載・加工を禁ず」とある。個人の範囲で使い、公開しない。
- **取得コマンド**（取得済みのページは再取得しない。間隔は 300ms）:
  ```bash
  deno run --allow-net --allow-read --allow-write tools/jreast_fetch.ts config/jreast/suica_penguin_net.json --service holiday
  ```

## 5. 探索プログラム `tools/rally_jreast.ts`

```bash
deno run --allow-read --allow-write tools/rally_jreast.ts --start 05:00-08:00/15 [--skip 仙台,新潟] [--json out/rally.json]
```

**移動の計算**: Connection Scan で行う。
- 同じ列車ページの続き（環状運転や列車番号の変更）は、乗ったまま扱う。
- 乗換時間は通常3分。東京・新宿は5分、上野・大宮・横浜・品川・池袋・渋谷は4分。新幹線と在来線の間は、さらに5分を足す。
- スタンプを押した後に新幹線に乗るときも、新幹線ホームへの移動として5分を足す。
- 除外: 運転日に「平日」を含む列車と、種別に「特急」「ライナー」を含む列車。
- 新幹線は、出発駅か到着駅が仙台・新潟のときだけ使う。

**回る順番**: Held-Karp で、全部の組み合わせから厳密に最も早く終わる順番を求める。
- 状態は (回ったタスクの集合, 最後のタスク) で、値は最も早くホームに戻れる時刻。
- 移動時間の表は、タスクのある駅ごとに 4:00〜26:00 を1分刻みで前もって計算する（約32秒）。順番の探索は、開始時刻1つあたり約2.7秒。

**タスク**: 駅とスポットを合わせて19タスクで、スタンプは20個。
- 各タスクは「ホームから片道 walk 分歩いてタッチ（1分）、片道 walk 分歩いてホームに戻る」とする。
- タッチの時刻が対応時間内に入るようにする。開く前に着いたら待つ。
- タスクの内容（片道の分数と時間）は `TASKS` 配列に直接書いている。spots.json からは読み込んでいない。
- 最初のタスクは首都圏のスポットに限る（仙台・新潟から始めない）。`--start-far` を付けると、この制限を外せる。

**開始時刻**: `--start` で、最初のスポットに着く時刻を振る。出発する駅（自宅の最寄りなど）からの移動は、まだ入っていない。

## 7. 経路の詳細（調べた根拠）

- **大井町TRACKS**:
  1. 京浜東北線ホームの品川寄りの階段（構内図の B）で上がり、トラックス口（2026年3月新設、IC カード専用）を出る。
  2. 3F の STATION PLAZA → TRACKS STREET-EAST を約140m → CROSS PLAZA のエスカレーターで 1F へ下りる → 北ロータリー南側の柱（タグ）。
  - 歩く距離は約190m で、ほかに階段1層とエスカレーター2層がある。
  - 根拠: OIMACHI TRACKS 公式フロアガイド（`https://www.oimachi-tracks.com/floor/`、地図は `assets/images/floor/map_01〜05.svg`）、JR 大井町駅構内図、UR 都市機構の交通広場の資料、ユーザー提供の写真。
- **上野**: 構内図で確認した。ホーム（2F）、エキュート上野（改札内3F）、中央改札（1F）の位置関係。
  - 山手線・京浜東北線のホームから中2Fの中央乗換通路を通って中央改札へ下りられる。
  - エキュートの営業時間は公式の店舗ページ（ecute.jp/ueno/shop/4471）で確認した。
- **新潟**: 構内図（2F）で、東側みどりの窓口が新幹線東改札・在来東改札を出てすぐの場所にあると確認した。
- **新宿**: みどりの窓口と指定席券売機の営業時間は、JR東日本の駅の情報（StationCd=866）で確認した。
- **OSM の徒歩**: Nominatim で位置を出し、routing.openstreetmap.de（foot）で経路の距離を出した。距離 ×1.03 ÷ 80m/分 で分に直している。
  - Google マップや現地では、まだ確かめていない。
  - curl は TLS で失敗するので、Deno の fetch を使う。

## 8. 次にやること（候補）

1. **出発地の指定**: 出発する駅と時刻を入力にし、そこから最初のスポットまでの移動も含めて計算する。終わった後に帰る駅（新潟からの帰りなど）も条件にする。
2. **徒歩と乗換時間の確認**: 現地や Google マップで確かめる。
   - とくに、上野の中央改札から新幹線ホーム、大宮の新幹線と在来線の乗り換え、池袋の南改札とメトロポリタン口の関係（今は別々のタスクとして往復を2回数えている）。
3. **タスク定義の整理**: `TASKS` を spots.json から作るようにする。
   - 改札内・改札外や、時間帯で場所を切り替えるタグ（上野・大宮）を、時間ごとに正しく扱えるようにする。
4. **表示**: 京王のときと同じように、行程をダイヤグラム（`tools/render_itinerary.ts` を参考）や、スマホ用の再計算画面（`web/replan/`）に載せる。
5. **ほかの条件**: 18か所（`--skip 仙台,新潟`）、平日ダイヤ（`--service weekday` で取得し直す）、特典の引き換え（11:00〜18:00）を途中に入れる案。
6. 横須賀線の駅時刻表が 0 本になる原因を調べる。
