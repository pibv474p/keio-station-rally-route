# 引き継ぎ: 別のスタンプラリーのルートを計算するとき

作成: 2026-10-18。

このリポジトリ（`train-diagram/`）では、これまでに2つのスタンプラリーのルートを計算した。

- 京王の全駅下車スタンプラリー（「京王沿線の想い出 ペッタン・ポン デジタルスタンプラリー」）
  - 2026-10-10 にユーザーが実際に回った。
- JR東日本の「Suicaのペンギン デジタルスタンプラリー」
  - 個別の資料は [handoff_suica_penguin.md](handoff_suica_penguin.md) にある。

新しいスタンプラリーで同じことをするときの手順と、注意すべき点を、ここにまとめる。

## 1. ユーザーについての前提

- **言葉**: 報告や質問（選択肢を含む）は日本語で書く。
- **実行環境**: Deno 2.x だけを使う（node / npm はない）。Windows 10 で、Git Bash と PowerShell が使える。
  - CPU は P コア＋E コア。並列で動かすときは `deno task visit` のように affinity `0xFFF5500` を使い、P コア 0〜3 を空けておく。
- **Git**: コミットはローカルまで。GitHub（`pibv474p/keio-station-rally-route`、公開）への push は、言われたときだけ行う。
- **データの扱い**: 時刻表の生データと生成物（`raw/`、`data/`、`out/`）はリポジトリに入れない。どの時刻表サイトも、公開 API でないか、転載が禁止されている。
- **写真やスクリーンショット**: ユーザーはスマホのアプリ画面などを、リモートコントロール経由で Claude アプリから送れる。
- **現地での確認**: ユーザーは実際に回る。乗り換えや徒歩の時間が短すぎると、現地で崩れたと指摘される。
  - 徒歩の時間は短めに見積もらない。
  - 徒歩の区間は、ユーザーが Google マップで確かめてくれることが多い。
- **公開の方法**: 結果は Artifact（非公開ページ）や A3 横の PDF で渡すと喜ばれる。これまでに作ったもの:
  - ダイヤグラムに行程を重ねた図
  - スマホ用の再計算画面

## 2. 進め方（これまでの流れ）

### ① スタンプラリーの中身を確かめる
- 公式の案内ページから、対象スポットの一覧、期間、特典と引換場所を読む。
- **タグ（スタンプ）の正確な位置と対応時間**は、公式ページやブログには、ほとんど載っていない。
  - エキタグなどのアプリの中にあるので、**ユーザーにスクリーンショットを送ってもらう**のが一番早くて確実。
  - 確認すること: 改札内か改札外か、どの改札口か、何階か、時間（始発〜終電、または施設の営業時間）、1か所で複数のスタンプが取れるか。
- 1つのスポットで、タグが複数の場所から選べることがある。
  - 例: ペンスタ上野は「改札内の店舗」か「駅の中央改札外」、ペンスタ新宿は「新宿駅のみどりの窓口」で駅のスタンプと同時に取れる。
  - 時間帯によって、どちらを使うかが変わる。

### ② 時刻表を取る
- 列車ごとの全停車駅の時刻まで取る。駅の発車時刻だけでは足りない。
  - 終点で終わる列車を拾うため、反対側の駅の時刻表からも取る。
- 平日か土休日かは、ユーザーに決めてもらう。
  - 臨時ダイヤ（京王の東京競馬開催日など）があるときは、その日の時刻表を日付指定で取る。
- 実装済みの取得元:

| 取得元 | 対象 | コマンド |
|---|---|---|
| NAVITIME の JSON API（`transfer-train.navitime.biz/api/keio/...`） | 京王 | `deno task fetch --line <config> --service holiday --date YYYY-MM-DD` → `deno task build ...` |
| JR東日本 公式時刻表の HTML（`timetables.jreast.co.jp`） | JR東日本 | `deno run --allow-net --allow-read --allow-write tools/jreast_fetch.ts config/jreast/<id>.json --service holiday` |

- 新しい会社の時刻表を足すときは、`src/sources/<name>/` にアダプタを作る（README の「ODPT / GTFS-JP を追加するとき」も参照）。
  - 出力は、正規化モデル（`src/model.ts`。時刻は0時からの秒、24時以降は 86400 以上）か、jreast と同じ「列車＝停車駅の並び」の JSON にする。
  - 公式サイトの画面が裏で JSON を取っていれば、それを使うのが楽（京王）。なければ HTML を解析する（JR）。
  - どちらの場合も、リクエストの間隔は 300ms 以上あける。取得済みのページは再取得しない。
- ODPT や GTFS-JP は、ライセンス（チャレンジ限定など）と、対象範囲（新幹線を含まないなど）を先に確かめる。

### ③ スポットの位置と、ホームからの往復時間
- 各スポットについて「ホームからタグまでの片道の分数」を決める。改札を出る時間や、建物の階の移動も含める。
- 調べ方:
  - 駅の構内図。JR東日本は `https://www.jreast.co.jp/estation/stations/<駅コード>.html` に PNG がある。画像の直接ダウンロードは 403 になるので、内蔵ブラウザで開き、canvas で切り出して拡大する。
  - 施設のフロアガイド。SVG なら取得して拡大する。
  - OSM: Nominatim で位置を出し、`routing.openstreetmap.de` の foot で歩行経路の距離を出す。
    - 補正係数 1.03 を掛けて、分速80m で分に直す。
    - curl は TLS で失敗するので、Deno の fetch を使う。
    - Overpass はつながらないことがある。
  - PDF の資料は、`pdftoppm` がない。内蔵ブラウザで pdf.js（cdnjs）を使って描く（`.claude/launch.json` の `scratch-files` に、scratchpad を配信する設定がある）。
- 構内図やフロアガイドから見積もった時間は、あとで現地か Google マップで確かめる。
  - 大井町TRACKS は、最初に3分と置いたが、実際は約5分（乗る車両で4〜6分）だった。

### ④ 探索

スポットの数で、使う道具を変える。

| 規模 | 道具 | 中身 |
|---|---|---|
| 約20か所まで（会社をまたぐ、時間の制約がある） | `tools/rally_jreast.ts` | Connection Scan で移動時間の表を作り、Held-Karp で厳密に解く。19タスクで、開始時刻1つあたり約3秒 |
| 数十〜80駅（1つの路線網の全駅） | `tools/visit_network.ts` ＋ `visit_core.ts` | Connection Scan ＋ビームサーチ＋局所探索。Worker で並列に動かす。開始時刻を振って比べる（`--sweep`） |

- `rally_jreast.ts` のタスク（駅、片道の分数、対応時間、スタンプ数）は、今はファイルの中の `TASKS` 配列に直接書いている。別のスタンプラリーで使うときは、設定ファイルから読むようにすると使い回せる。
- 守るべき決まり（過去にユーザーから指摘されたもの）:
  - 改札を出ずに、逆方向の列車に乗り換えるときは、別のホームへ移る時間（+3分）を入れる。
  - 指定の改札がホームとつながっていない駅は、その分を足す（京王: 千歳烏山・柴崎）。
  - 最後のスポットで長く滞在する場合も、完了時刻に含める。
  - 臨時停車の可能性（京王の土休日の飛田給）は、その先を1分遅れとして扱う。
  - 有料の列車（特急、ライナー、座席指定）は使わない。新幹線は、ユーザーが許した区間だけで使う。
  - 徒歩でのショートカットは、次の電車を待つより早いときだけ選ぶ。
  - スタンプの後に新幹線へ乗るときは、新幹線ホームへの移動時間を入れる。
- 結果は「最初のスポットに着く時刻」ごとに、完了時刻と所要時間を一覧にする。そのうえで、良い案を2つほど行程つきで示す。
  - 一番きつい乗り換えや、遅れに備えた余裕がないことも、必ず書く。

### ⑤ 見せ方
- **ダイヤグラム**: `tools/render_itinerary.ts`（京王用）は、路線網のダイヤに行程を重ねた HTML を作る。A3 横で印刷できる。
  - PDF は Edge headless の `--print-to-pdf` で作る。`--user-data-dir` は毎回別の場所にする。
- **スマホ用の再計算画面**: `web/replan/`（京王用）。今いる駅、時刻、訪問済みのスポットから、残りのルートを端末の中で計算し直す。
  - Artifact として公開し、db 機能を使う。作り方は README を参照。
- 別のスタンプラリーに使うときは、データの形式（駅の ID、路線）に合わせて手を入れる必要がある。

## 3. つまずいた点

- 内蔵ブラウザでは、外部ページから localhost への fetch や iframe が使えず、貼り付けも届かない。大きなデータを渡すときは `tools/send_server.ts` を使う。
- PDF の URL を内蔵ブラウザで開くと、ダウンロードの保存画面がユーザーに出てしまう。開く前に、WebFetch か Deno で取る。
- Cookie の同意画面は、勝手に「同意」を押さない。調べるだけなら、ページのデータを JavaScript で読む。
- JR の駅時刻表では、0時台の列車は翌日として扱う。列車ページの時刻は、深夜に日付が変わるので、単調に増えるように直す。
- 長い処理（取得に十数分かかるもの）はバックグラウンドで動かし、ユーザーに途中経過を伝える。
